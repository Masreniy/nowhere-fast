# Агенты

> Адаптировано из ECC `rules/common/agents.md` (MIT). Таблица сокращена до
> четырёх агентов, которые у нас реально установлены. Оригинал перечислял
> одиннадцать, включая ревьюеров под Rust и HarmonyOS — у нас их нет, и ссылка
> на несуществующего агента хуже, чем её отсутствие.

## Установлены в `.claude/agents/`

| Агент | Назначение | Когда звать |
|---|---|---|
| `planner` | План реализации | Сложная фича, рефакторинг |
| `architect` | Проектирование системы | Архитектурное решение, выбор подхода |
| `code-reviewer` | Ревью качества | Сразу после написания кода |
| `security-reviewer` | Поиск уязвимостей | Перед коммитом кода, трогающего данные, права или разметку |

## Когда звать без отдельной просьбы

1. Запрос на сложную фичу → **planner**
2. Код только что написан или изменён → **code-reviewer**
3. Архитектурное решение → **architect**
4. Затронуты данные, права или вставка в HTML → **security-reviewer**

## Контракт делегирования

Если агент делегировал работу — он обязан дождаться результата и собрать его.
Ответ «жду фоновые задачи» не является выполненной работой: завершив ход, пока
дочерние задачи ещё идут, их результаты теряются.

Декомпозировать стоит только тогда, когда работа не помещается в один контекст.
Не дробить задачу, которая и так помещается.

## Разбор с нескольких точек зрения

Для сложных решений полезно прогнать одну задачу через разные роли: фактчекер,
senior-инженер, специалист по безопасности, проверяющий на противоречия.
