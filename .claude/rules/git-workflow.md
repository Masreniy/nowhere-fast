## Формат коммита

```
<тип>: <описание>

<необязательное тело>
```

Типы: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `ci`

Описание — в повелительном наклонении, по существу: что изменилось и зачем.
История коммитов в этом репозитории начиналась с сообщений вроде «еще одно» и
«снова обновление» — так больше не делаем.

## Ветки

- Работа ведётся в ветке, не в `main`
- Имя ветки отражает задачу

## Pull request

1. Смотреть всю историю ветки, а не последний коммит: `git diff main...HEAD`
2. В описании — что изменилось, зачем, и как это проверить
3. Пушить новую ветку с `-u`

## Что не коммитим

- Секреты любого вида
- Отладочный код
- Закомментированные куски «на всякий случай» — для этого есть история git
