# Nowhere Fast — Foundation

> **Статус: исторический документ.** Это самый ранний документ проекта, он старше
> всех ADR. В части **порядка работ** он заменён решениями владельца:
>
> - [ADR-0002](adr/0002-mvp-scope-and-anti-goal.md) — объём первой версии и анти-цель
> - [ADR-0003](adr/0003-place-data-sources.md) — источники данных о местах
> - [ADR-0004](adr/0004-places-as-first-class-entity.md) — место как самостоятельная сущность
> - [ADR-0005](adr/0005-apply-rls-before-auth.md) — RLS применён до появления входа
>
> Где документ расходится с ADR — прав ADR. Раздел «Этапы» ниже уже приведён
> в соответствие; прежняя редакция сохранена в конце файла.

## Архитектура

Проект переходит от монолитных HTML-файлов к слоям: общая UI-система → слой данных →
доменные сущности → страницы.

Сделано: `assets/css/app.css` (токены и дизайн-система), `assets/js/dom.js`
(единственная точка вывода данных), `assets/js/api.js` (единственное место, знающее
про таблицы), `assets/js/config.js` (ключи и константы).

## Домен

Реальная схема — `supabase/schema.sql`. В базе ровно пять таблиц:

```
cities ──┬─> places                                          (ADR-0004)
         └─> route_templates → route_template_days → route_template_activities
```

`places` — основная сущность продукта ([ADR-0004](adr/0004-places-as-first-class-entity.md)).
Место принадлежит городу, а не маршруту, и переиспользуется в любом количестве планов.
Координаты обязательны ([ADR-0003](adr/0003-place-data-sources.md)): место без них
неразмещаемо во времени и пространстве и в план не попадает.

`route_template_activities` ссылается на место через `place_id`. Текстовые `name`
и `location` остались для уже введённых данных и в планировании не участвуют.

Поездки пользователя (`trips` и то, что вокруг них) в схеме отсутствуют: они требуют
аккаунтов, а аккаунты вынесены за пределы первой версии
([ADR-0002](adr/0002-mvp-scope-and-anti-goal.md)). Чек-листы сборов, обещанные ранним
замыслом, прямо перечислены в анти-цели того же ADR.

Примечание от 16.09.2026: таблицы с похожими именами (`trips`, `trip_activities`,
`trip_packing`, `users`) в базе уже лежали — пустые и не связанные с кодом. Они
удалены, см. `supabase/cleanup-legacy.sql`. Если такие таблицы появятся снова, они
начнутся с чистого листа.

## Этапы

Порядок задаётся [ADR-0002](adr/0002-mvp-scope-and-anti-goal.md): первой проверяется
основная гипотеза — связность маршрута. Всё, что её не проверяет, идёт после.

1. **Основание.** Дизайн-система, единый слой данных, схема, индексы, ограничения, RLS.
   Сделано; RLS применён 16.09.2026 ([ADR-0005](adr/0005-apply-rls-before-auth.md)).
2. **Публичный контент.** Города, маршруты, дни, активности — страницы работают,
   читаются только опубликованные записи. Контента почти нет: 1 город, 1 опубликованный
   маршрут, 0 мест (на 16.09.2026).
3. **Места с координатами.** Ручное наполнение первого города — этап 1 источников
   по [ADR-0003](adr/0003-place-data-sources.md), сущность по
   [ADR-0004](adr/0004-places-as-first-class-entity.md). Заводятся через интерфейс
   Supabase или MCP-коннектор: `admin.html` не пишет, пока нет входа
   ([ADR-0005](adr/0005-apply-rls-before-auth.md)).
   Объём наполнения не зафиксирован — **требует решения владельца**
   (открытый вопрос 5 в `PRODUCT-BRIEF.md`).
4. **Планировщик связного маршрута.** Город + даты + несколько мест → план по дням
   без возвратов, крюков и провалов по времени, с подсказкой «что рядом».
   Это и есть первая версия ([ADR-0002](adr/0002-mvp-scope-and-anti-goal.md)).
5. **Импорт из карт.** Этап 2 источников ([ADR-0003](adr/0003-place-data-sources.md)).
   Провайдер не выбран: [ADR-0006](adr/0006-map-provider.md) в статусе `proposed`,
   вопрос лицензионный — **требует решения владельца**.
6. **Авторы-блогеры.** Этап 3 источников ([ADR-0003](adr/0003-place-data-sources.md)).
   Требует аккаунтов, то есть отдельного решения владельца (см. ниже).
7. **ИИ.** Только обогащение: описания, теги, черновики группировки. Не источник
   факта о существовании места, адресе, координатах, часах и ценах —
   ограничение [ADR-0003](adr/0003-place-data-sources.md), снимается только новым ADR.

### Вне первой версии

Не «потом когда-нибудь», а «не раньше, чем владелец примет отдельное решение и
появится новый ADR, отменяющий ADR-0002».

| Что | Почему отложено |
|---|---|
| Аккаунты и Supabase Auth | Вне первой версии — [ADR-0002](adr/0002-mvp-scope-and-anti-goal.md), альтернатива 3: недели работы до первой проверки гипотезы |
| CMS: запись из `admin.html`, публикация | Зависит от входа; сейчас запись закрыта RLS ([ADR-0005](adr/0005-apply-rls-before-auth.md)) |
| Поездки пользователя, «Мои поездки», память о посещённом | Требуют аккаунтов ([ADR-0002](adr/0002-mvp-scope-and-anti-goal.md)) |
| Чек-листы сборов | Прямо в анти-цели [ADR-0002](adr/0002-mvp-scope-and-anti-goal.md) |
| Маркетплейс маршрутов, выплаты, билеты, eSIM, мобильное приложение, трекинг рейсов | Анти-цель [ADR-0002](adr/0002-mvp-scope-and-anti-goal.md) |
| Print/PDF | ADR не закрывают — **требует решения владельца** |

## Главное изменение

Локальный пароль в JavaScript не является механизмом безопасности и не используется
в новой архитектуре. Доступ к изменению данных определяется Supabase Auth + RLS.

Первая редакция этого документа задавала такой порядок:

1. Foundation: дизайн-система, единый data layer, SQL schema, indexes, constraints, RLS.
2. Public content: города, маршруты, дни, активности.
3. CMS: Supabase Auth, администраторы, CRUD и публикация.
4. Trip planner: поездки, даты, прогресс, чек-листы.
5. Maps.
6. Accounts.
7. Print/PDF.
8. AI.

Домен описывался так: `cities` → `route_templates` → `route_template_days` →
`route_template_activities`, а после стабилизации CMS — `trips` → `trip_days` →
`trip_items` и чек-листы.

**Почему изменилось:** [ADR-0002](adr/0002-mvp-scope-and-anti-goal.md) решил, что
первая версия — это планировщик связного маршрута, а вход, аккаунты и чек-листы
сборов вынесены за её пределы. Прежний порядок ставил вход третьим шагом,
а планировщик — четвёртым, то есть основная гипотеза проверялась бы последней.

</details>
