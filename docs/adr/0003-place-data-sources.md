# ADR-0003: Источники данных о местах — все четыре, но по этапам и с ограничением на ИИ

**Дата**: 2026-09-13
**Статус**: accepted
**Участники**: владелец проекта, Claude

## Контекст

Планировщик связного маршрута (ADR-0002) бесполезен без данных: нечего связывать.
На вопрос об источнике мест владелец ответил «все варианты» — ручное наполнение,
импорт из карт, авторы-блогеры и генерация ИИ.

Ответ верен на горизонте продукта, но как руководство к действию он неполон:
источники несовместимы по времени включения и неравноценны по риску. Один из них
способен разрушить доверие к продукту необратимо.

Отдельное обстоятельство: боль «в 10 минутах было что-то ещё» **невозможно** решить
без координат и времени в пути. Текущая схема хранит у активности только текстовое
поле `location`. Никакой источник данных не спасёт, если координаты не хранятся.

## Решение

Используем все четыре источника, но включаем их по этапам, и один ограничиваем жёстко.

**Обязательное условие для любого источника:** место хранится с координатами
(широта, долгота). Место без координат в планировщик не попадает — оно неразмещаемо
во времени и пространстве.

| Этап | Источник | Роль |
|---|---|---|
| 1 | **Ручное наполнение владельцем** | Один город, десятки мест. Проверка гипотезы |
| 2 | **Импорт из карт** (OSM/Overpass, при необходимости Google Places) | Координаты, адреса, категории, время в пути. Масштаб |
| 3 | **Авторы-блогеры** | То самое знание «куда ходят местные», которого нет в картах |
| 4 | **ИИ** | Только обогащение, см. ограничение ниже |

**Ограничение на ИИ (не подлежит смягчению без нового ADR):** модель **не является
источником истины о существовании места, его адресе, координатах, часах работы и
ценах.** ИИ допускается для описаний, тегов, черновиков группировки и подсказок по
последовательности — то есть там, где ошибка стоит неловкости, а не сорванной поездки.
Любой факт, который пользователь может проверить ногами, приходит из карт, от
владельца или от автора.

## Рассмотренные альтернативы

### Альтернатива 1: Включить все источники сразу
- **За**: буквально соответствует ответу владельца; максимум данных с первого дня
- **Против**: авторы требуют аккаунтов, редактора и модерации — это отдельный продукт (и он в анти-цели ADR-0002). Импорт из карт требует решения по провайдеру и лимитам. Одновременный старт четырёх направлений означает, что ни одно не доведено
- **Почему нет**: это не отказ от источников, а их упорядочивание. Все четыре остаются в плане

### Альтернатива 2: Только карты, без ручного наполнения
- **За**: сразу много городов; координаты есть по определению; не надо ничего писать руками
- **Против**: карты содержат объекты, но не содержат смысла. «Куда ходят местные», почему это место стоит вечера, что рядом стоит совместить — этого в OSM нет. Ровно это владелец описывал как боль: в Китае такие места живут в TikTok, а не в справочнике
- **Почему нет**: планировщик из одних карт превратится в список POI — то есть в то, что уже делает Trip.com

### Альтернатива 3: Только ИИ-генерация
- **За**: быстро, дёшево, сразу много городов
- **Против**: модели уверенно выдумывают заведения, путают адреса и часы работы. Одна поездка в несуществующий ресторан на другом конце города убивает доверие навсегда — а доверие и есть весь продукт
- **Почему нет**: риск несоразмерен выигрышу; допускается только как обогащение поверх проверенных данных

### Альтернатива 4: Не хранить координаты, обойтись текстовым адресом
- **За**: не меняем схему; проще наполнять
- **Против**: без координат нельзя посчитать ни время в пути, ни «что рядом», ни отсутствие крюков. То есть нельзя сделать ровно то, ради чего затевается продукт
- **Почему нет**: это отказ от основной гипотезы под видом экономии

## Последствия

### Положительные
- Есть однозначный ответ на вопрос «откуда взять место» на каждом этапе
- Правило про координаты защищает схему данных от того, чтобы её пришлось переделывать после наполнения
- Ограничение на ИИ защищает доверие — единственный актив, который нельзя восстановить

### Отрицательные
- Первый город наполняется руками; это медленно и не масштабируется
- Импорт из карт — отдельная работа, которой пока нет в оценке
- Часть ценности («куда ходят местные») недоступна до этапа 3

### Риски
- **Ручное наполнение не будет доведено, и планировщику нечего будет планировать.**
  Смягчение: объём первого города фиксируется до начала разработки — иначе наполнение
  превращается в бесконечную задачу
- **Выбор провайдера карт (OSM против Google Places) отложен.** Это отдельное решение
  с последствиями по лицензии, стоимости и качеству данных; оформляется своим ADR,
  когда дойдём до этапа 2
- **Соблазн нарушить ограничение на ИИ, когда наполнение окажется медленным.**
  Смягчение: ограничение записано здесь явно и снимается только новым ADR
