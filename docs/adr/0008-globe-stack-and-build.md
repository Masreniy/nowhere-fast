# ADR-0008: Движок глобуса собирается заранее и коммитится; страница глобуса требует сервера

**Дата**: 2026-09-16
**Статус**: accepted
**Участники**: владелец проекта (постановка и решение), Claude (разбор и предложение)

## Контекст

Владелец попросил трёхмерный глобус как вход в продукт и согласовал прототип.
Глобус построен на `three.js@0.186` и `three-globe@2.45.2`.

Проект держится на двух правилах стека: **сборки нет** и **страницы открываются
с `file://`** (скрипты подключаются классическими тегами, не модулями). Глобус
задевает оба. Ниже — что именно проверено, а не предположено.

Про библиотеки:

- У `three@0.186` UMD-сборки **не существует**: `package.json` объявляет
  `"type": "module"`, в `build/` только ESM, `grep define.amd` по всему каталогу
  даёт ноль. `three.cjs` — заглушка на 631 байт с текстом о депрекации.
- У `three-globe` UMD-сборка есть, но весит **3 995 599 байт**: внутрь запечён
  движок WebGPU (`WebGPUBackend` — 27 вхождений) и `h3-js`, которыми мы
  не пользуемся. Её UMD-обёртка к тому же требует глобальный `THREE` снаружи,
  а взять его неоткуда — см. предыдущий пункт.
- Тот же `three-globe`, собранный с заглушками на мёртвые ветки, — **332 339
  байт**. Вместе с `three` — 1 066 608 байт, 299 854 после gzip.

Про `file://` — замерено в Chromium, тексты ошибок дословно:

| Что | `file://` | `http://` |
|---|---|---|
| классический `<script src>` | работает | работает |
| `<script type="module">` | `blocked by CORS policy: Cross origin requests are only supported for protocol schemes: chrome, …, http, https` | работает |
| `fetch` и `XMLHttpRequest` к соседнему файлу | та же ошибка CORS | работает |
| `<img src="./pic.png">` | грузится | грузится |
| `getImageData` для неё | `SecurityError: … The canvas has been tainted by cross-origin data.` | работает |
| `gl.texImage2D` для неё | `SecurityError: … The image element contains cross-origin data, and may not be loaded.` | работает |
| `data:`-картинка в canvas и в WebGL | работает | работает |

Ключевое: сам контекст WebGL на `file://` создаётся. Ломается **передача
текстуры**, загруженной из соседнего файла.

## Решение

**Первое.** Движок собирается заранее и кладётся в репозиторий готовым файлом:
`assets/vendor/globe-engine.js` — одна классическая IIFE-сборка `three` +
`three-globe` с заглушками на `three/webgpu`, `three/tsl` и `h3-js`. Исходники
сборки — в `tools/globe/`, они в продакшен не попадают. Страница подключает
артефакт обычным тегом.

Правило «сборки нет» этим **не отменяется**: на сайте по-прежнему нет шага
сборки, публикуется то, что лежит в репозитории. Сборка — разовое действие
разработчика при обновлении версии библиотеки, как обновление вендоренной
зависимости.

**Второе.** `globe.html` работает по `http/https` и **не поддерживает
`file://`**. Открытая с файла, она показывает текст с объяснением, а не чёрный
экран. Остальные страницы проекта продолжают открываться с `file://` как раньше.

Это сознательное сужение правила, а не его отмена. Причина названа выше: карта
Земли — растровое изображение, а браузер запрещает отдать в WebGL картинку,
загруженную с `file://`.

## Рассмотренные альтернативы

### Альтернатива 1: подключить библиотеки с CDN, как `supabase-js`

- **За**: ровно тот способ, которым проект уже пользуется; ничего не коммитим;
  обновление версии — правка одной строки
- **Против**: у `three` нет UMD-сборки вовсе, а UMD `three-globe` весит 4 МБ
  и всё равно требует глобальный `THREE`, которого не существует
- **Почему нет**: не техническое предпочтение, а отсутствие предмета. Подключать
  нечего

### Альтернатива 2: перевести страницу глобуса на ES-модули и импортмапы

- **За**: без сборки; современный способ; версии видны в разметке
- **Против**: ES-модули не работают с `file://` вовсе — то есть цена та же, что
  у принятого решения, но сверху ложится загрузка десятков файлов по сети и
  зависимость от доступности CDN в момент открытия страницы
- **Почему нет**: платим ту же цену, получаем меньше

### Альтернатива 3: вшить всё в одну страницу как `data:`-URI

- **За**: `file://` продолжает работать полностью — это единственный вариант,
  который сохраняет правило целиком; проверено, что `data:`-картинки проходят
  и в canvas, и в WebGL
- **Против**: одна страница на 3,3 МБ, которую браузер разбирает целиком при
  каждом открытии; кэшировать по частям нельзя; ровно это владелец и назвал
  неправильным — «мы всё сейчас в один файл напихали»
- **Почему нет**: сохраняет букву правила ценой того, ради чего правило есть

### Альтернатива 4: отдавать текстуры из Supabase Storage

- **За**: `https` работает и со страницы, открытой с `file://`, — правило
  сохраняется полностью, а файлы остаются раздельными и кэшируются
- **Против**: картинки уезжают из репозитория в сервис, появляется зависимость
  от сети там, где её раньше не было, и трафик на тарифе Supabase; версия
  текстуры перестаёт быть видна в истории git
- **Почему нет**: отказа нет, это живой запасной вариант. Не выбран, потому что
  разменивает прозрачность репозитория на удобство, которым пользуется только
  разработчик

## Последствия

### Положительные

- Вес страницы честный: 1,07 МБ движка (300 КБ по сети) вместо 4 МБ UMD-сборки
- Что опубликовано — то и лежит в репозитории; сборка не участвует в выкладке
- Версия библиотеки видна в истории git вместе с последствиями обновления

### Отрицательные

- В репозитории появился собранный файл, который нельзя читать и нельзя править
  руками. Смягчение: шапка файла говорит, чем собран и какой командой
  пересобирается; исходник рядом, в `tools/globe/`
- Правило «страницы открываются с `file://`» перестало быть общим: у него теперь
  есть исключение, и о нём надо помнить
- Обновление `three` требует установить сборочные зависимости и прогнать сборку —
  на одну ступеньку сложнее, чем поправить номер версии в теге

### Риски

- **Артефакт разойдётся с исходником.** Кто-то поправит `tools/globe/`,
  забудет пересобрать, и в репозитории будет лежать старый движок. Смягчение:
  пока — README и ревью; полноценно закрывается проверкой в CI, которая
  пересобирает и сравнивает. Не сделано
- **Собранный файл невозможно просмотреть на ревью.** Изменение в нём выглядит
  как «поменялся 1 МБ минифицированного кода». Смягчение: артефакт меняется
  только вместе с явным изменением версии в `tools/globe/package.json`
- **Правило с исключением слабее правила без исключения.** Следующий, кому
  «тоже нужен fetch», сошлётся на этот ADR. Смягчение: причина здесь названа
  конкретно — запрет браузера на чтение пикселей чужого файла, — а не
  «так удобнее»
