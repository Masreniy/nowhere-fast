# tools/globe — сборка артефактов глобуса

Здесь живут скрипты, которые готовят большие файлы для страницы глобуса.
**В продакшен эта папка не попадает.** В браузер уезжают только готовые
артефакты из `assets/`, и они лежат в репозитории готовыми.

## Почему вообще нужна сборка, а не CDN

Проект подключает скрипты классическими тегами `<script src>`, без
`type="module"` — так страницы открываются даже с `file://`. Взять `three`
с CDN одним тегом не получится по двум причинам, и обе проверены, а не
предположены:

1. **У `three@0.186` UMD-сборки нет вовсе.** Пакет поставляется только как
   ES-модули: `grep define.amd` по `node_modules/three/build/` даёт ноль
   вхождений. Классический `<script>` такой файл не загрузит.
2. **UMD-сборка `three-globe` есть, но весит 4 МБ** (3 995 599 Б). Внутрь
   запечён движок WebGPU — `WebGPUBackend` встречается там 27 раз. Сцена
   создаёт обычный `WebGLRenderer`, и весь этот код мёртв: браузер только
   разбирает и компилирует его при загрузке.

Отсюда собственная сборка: esbuild складывает `three`, `three-globe` и
`three-geojson-geometry` в один IIFE и выкладывает наружу три имени в `NF`.
Ветки, которых в сцене нет (`three/webgpu`, `three/tsl`, `h3-js` — тайловая
карта и гексбины), подменяются заглушкой `src/stub-unused.js`. Заглушка
перечисляет имена поимённо: если новая версия `three-globe` попросит что-то
ещё, сборка упадёт с понятной ошибкой, а не тихо подсунет пустоту.

Результат: 1 042 КБ, 293 КБ gzip, ноль вхождений `WebGPUBackend`.

## Почему артефакты коммитятся

Это осознанное решение, зафиксированное в ADR-0008. Проект — статика без
сборки, публикуется на GitHub Pages прямо из `main`. Шага сборки при
публикации нет и заводить его ради одной страницы дороже, чем хранить
готовые файлы. Поэтому в репозитории лежат:

| Артефакт | Что это | Чем собран |
|---|---|---|
| `assets/vendor/globe-engine.js` | three + three-globe + three-geojson-geometry | `build-vendor.js` |
| `assets/img/globe/earth.jpg` | снимок поверхности, 4096×2048 | `build-textures.js` |
| `assets/img/globe/surface.jpg` | R рельеф, G ночные огни, B маска суши, 2048×1024 | `build-textures.js` |
| `assets/data/globe-stars.js` | каталог звёзд и линии созвездий | `build-stars.js` |

Все четыре начинаются шапкой «собрано автоматически, руками не правится».
Правка артефакта руками пропадёт при следующей пересборке — менять надо
скрипт здесь.

## Как пересобрать

Один раз поставить зависимости сборки:

```
cd tools/globe && npm install
```

Корневой `package.json` этих зависимостей **не получает**: там только `jsdom`
для тестов. Дальше из корня репозитория:

```
npm run build:globe-vendor      # assets/vendor/globe-engine.js      ~1 с
npm run build:globe-textures    # assets/img/globe/*.jpg             ~2,5 мин
npm run build:globe-stars       # assets/data/globe-stars.js         ~1 с
```

`build-textures.js` почти всё время считает растр стран 4096×2048 (точка
в полигоне для восьми миллионов пикселей). Результат кладётся в
`tools/globe/.cache/` и при следующем запуске берётся оттуда; пересчитать
принудительно — `TEX_FORCE=1`. Размер текстур меняется переменными `TEX_W`
и `TEX_H`.

## Что проверяют сами скрипты

Сборка не верит себе на слово:

- `build-textures.js` декодирует получившийся `surface.jpg` обратно и сверяет
  маску суши попиксельно — все 2 097 152 точки обязаны остаться по ту же
  сторону порога. На маске держатся блики по воде и рельефная тень только
  по земле; «JPEG вроде бы не портит двоичный канал» здесь недостаточно.
  Заодно печатает яркость огней в пяти известных точках: Токио и Москва
  должны гореть, океан, Сахара и Амазония — молчать.
- `build-stars.js` разворачивает упакованные координаты обратно и сверяет
  с исходником: 16-битная сетка по прямому восхождению даёт шаг 0,0055°,
  по склонению — сотую градуса. Всё, что грубее, — ошибка упаковки.

## Чего здесь нет

**Карты стран `index.png`** из прототипа. Там страна по клику определялась
чтением пикселя из текстуры-индекса; в проекте это делается по контурам
на стороне сцены, и растровая карта стран не нужна. Растр стран всё равно
считается — но только как источник маски суши, наружу он не выходит.

**Справочника стран и городов.** Он живёт в базе (ADR-0010), а не в файле
рядом с кодом. Зависимости `world-atlas`, `all-the-cities` и
`i18n-iso-countries` стоят здесь потому, что ими готовится содержимое
таблиц `countries` и `geo_cities`.
