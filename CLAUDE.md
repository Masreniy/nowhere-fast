# Nowhere Fast

Планировщик путешествий. Статический фронтенд, данные — в Supabase.

## Состояние проекта

**Ранняя стадия.** Продуктовое видение зафиксировано в
[docs/PRODUCT-BRIEF.md](docs/PRODUCT-BRIEF.md) — читай его перед любой продуктовой
работой. Раздел «Ответы владельца» там подтверждён, раздел «Предложения» — нет.
Не додумывай продуктовые решения за владельца: то, чего в брифе нет, спрашивай.

## Стек

- Чистый HTML/CSS/JS, без сборки, без npm, без фреймворка
- Supabase через CDN-клиент `@supabase/supabase-js@2`, запросы идут **прямо из браузера**
- Страницы открываются как статика, сервера нет

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | Лендинг + список городов из таблицы `cities` |
| `city.html` | Страница города по `?city=<имя>` + маршруты |
| `admin.html` | Админка: добавление и удаление городов и маршрутов |
| `assets/css/app.css` | Общая дизайн-система — **создана, но ни одной страницей не подключена** |
| `docs/FOUNDATION.md` | Архитектура и дорожная карта из 8 этапов |

## Модель данных

```
cities → route_templates → route_template_days → route_template_activities
```

Поля `cities`: `id, name, country, description, image_url, currency, language, timezone, visa_info`.

SQL-схемы в репозитории нет — структура выведена из запросов в коде. Это тоже пробел.

## Известный технический долг

Всё перечисленное установлено чтением кода, а не предположено. При работе рядом
с этими местами — чинить, а не обходить.

1. **XSS во всех трёх страницах.** Данные из БД и query-параметр `?city=`
   попадают в `innerHTML` без экранирования.
2. **Админка полностью открыта.** Аутентификации нет; защита данных целиком
   зависит от RLS в Supabase, а политик в репозитории нет — проверить нечем.
3. **`app.css` не подключён.** Дизайн-система продублирована inline в трёх файлах,
   токены уже разошлись.
4. **N+1 запросы** в `city.html`: маршруты → дни → активности загружаются в циклах.
5. **Поиск города по имени**, а не по `id` — ломается при переименовании,
   `.single()` падает на дубликатах.
6. **Админка не покрывает модель:** дни и активности через UI не создать,
   редактирования нет, поля `currency/language/timezone/visa_info` не заполнить.
7. **Хардкод «Гуанчжоу»** как города по умолчанию и как условия для тегов.

## С чего начинать

Порядок работы описан в [.claude/rules/development-workflow.md](.claude/rules/development-workflow.md).
Коротко: «зачем» зафиксировано в `docs/PRODUCT-BRIEF.md`; дальше — критерии приёмки
(`intent-driven-development`), план, код.

**Суть продукта одной строкой:** боль не в том, что человек не знает, *что*
посмотреть, а в том, что он не знает, *в каком порядке* — и теряет дни на возвраты,
крюки и простои. Всё остальное вторично.

## Правила

Все правила проекта — в [.claude/rules/](.claude/rules/README.md). Ключевое:

- Пользовательские данные **никогда** не идут в `innerHTML` — только `textContent`
- Единственная реальная граница безопасности — RLS на стороне Supabase,
  а не то, что скрыто в интерфейсе
- Продуктовые ограничения не выводятся из кода — только от владельца проекта
- Архитектурные развилки фиксируются в `docs/adr/`
