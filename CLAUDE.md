# Nowhere Fast

Планировщик путешествий. Статический фронтенд, данные — в Supabase.

## Состояние проекта

**Ранняя стадия.** Продуктовое видение зафиксировано в
[docs/PRODUCT-BRIEF.md](docs/PRODUCT-BRIEF.md) — читай его перед любой продуктовой
работой. Принятые решения — в [docs/adr/](docs/adr/README.md):

- **ADR-0002** — объём первой версии и анти-цель
- **ADR-0003** — источники данных о местах и ограничение на ИИ
- **ADR-0004** — место как самостоятельная сущность с координатами
- **ADR-0005** — RLS применён до появления входа; админка пишет только через Supabase
- **ADR-0006** — источник данных о местах: OpenStreetMap, атрибуция обязательна
- **ADR-0007** — страница города собирает поездку; состояние живёт в ссылке, без аккаунтов
- **ADR-0008** — движок глобуса собирается заранее и коммитится; первая страница требует сервера
- **ADR-0009** — язык, точка отсчёта и время — общий слой, а не свойство страницы
- **ADR-0010** — справочник стран и городов отдельными таблицами; лицензия каждого источника названа
- **ADR-0011** — справочник заливает скрипт с прямым подключением, а не человек по кусочкам

Не додумывай продуктовые решения за владельца: то, чего в брифе и ADR нет, спрашивай.
Открытые вопросы перечислены в конце брифа.

## Стек

- Чистый HTML/CSS/JS, без сборки и без фреймворка
- Supabase через CDN-клиент `@supabase/supabase-js@2`, запросы идут **прямо из браузера**
- Страницы открываются как статика; публикуются на GitHub Pages из `main`
- Скрипты подключаются классическими тегами, не модулями, — чтобы страницы
  открывались и с `file://`. **Исключение — `globe.html`**: браузер запрещает
  отдать в WebGL картинку, загруженную с соседнего файла, поэтому первая
  страница работает только по http (ADR-0008). Остальные — как раньше
- npm нужен для тестов (`npm install && npm test`) и для сборки движка глобуса
  (`tools/globe`, отдельные зависимости). В продакшен не попадает ни то, ни другое:
  публикуется то, что лежит в репозитории

## Модель данных

```
countries ─┬─> geo_cities                              (ADR-0010, справочник)
           └─> cities ──┬─> places                     (ADR-0004, продукт)
                        └─> route_templates → days → activities ──> places
```

Две половины модели живут по разным правилам, и путать их нельзя.

`cities` и всё под ней — **продукт**: город заводится руками, потому что за ним
стоит содержание. `countries` и `geo_cities` — **справочник**: 235 стран
и 9045 городов от 50 тысяч жителей, приходит из источников целиком
и заменяется целиком. Почему не одной таблицей — ADR-0010.

В источнике таких городов 9062. Семнадцать не попали: их страны нет
в `countries`, потому что у неё нет кода ISO. Девять из них — города
Косова, и это значит, что Приштина на глобусе не ищется. Владелец решил
16.09.2026 оставить как есть: заводить стране код, которого нет в стандарте,
значит занимать сторону в споре о признании. Разбор
и причина — в конце ADR-0010.

`places` — основная сущность планировщика. Координаты обязательны: место без них
неразмещаемо и в план не попадает. Поля `name_local` и `address_local` хранят
написание на языке страны — латиницу навигатор может не найти.

Схема лежит в `supabase/schema.sql`. Изначально она была реконструирована по коду;
**16.09.2026 сверена с живой базой** через MCP-коннектор Supabase — в два прохода.

Первый проход сравнил список таблиц и колонок. Второй, в тот же день, сравнил
**типы и признак `not null`** по `information_schema` — и нашёл ещё шесть расхождений:
`not null` не стоял на трёх внешних ключах, `created_at` у `cities` и `route_templates`
лежал без часового пояса, а три колонки активностей (`duration_minutes`, `type`,
`is_mandatory`) не были описаны вовсе. Всё исправлено, блок «Второй проход сверки»
в конце файла схемы.

Урок оттуда: «схема сверена» — это сравнение по `information_schema`, а не взгляд
на список таблиц. Колонка на месте ещё не значит, что она того же типа.

В базе ровно пять таблиц этой схемы и ничего лишнего. Четыре таблицы-наследия
(`users` с колонкой `password_hash`, `trips`, `trip_activities`, `trip_packing`)
были пусты, кодом не использовались и удалены 16.09.2026 — запись об этом
и причины в `supabase/cleanup-legacy.sql`.

Чего `schema.sql` не смог применить: поля и ограничения, объявленные **внутри**
`create table if not exists` для таблиц, которые уже существовали. Для уже созданной
таблицы этот оператор не делает ничего. Добавлено отдельными `alter` 16.09.2026.

Данные в базе на 17.09.2026 (проверено запросом): 1 продуктовый город
(Гуанчжоу / 广州, `country_code = 'CN'`), 2 маршрута (опубликован 1), 3 дня,
12 активностей, **50 мест**.

**Справочник залит и сверен с источником 17.09.2026.** 235 стран (234 из
генератора плюс Ватикан, см. техдолг №17) и **9045 городов** — ровно столько,
сколько обещает манифест. Сверка — не «посчитали строки»: у стран сошлись коды,
широты, долготы, размахи и все 32 323 точки очертаний; у городов — сумма
идентификаторов, населения, широт, долгот и хэш названий. Всё до единицы.
Как это проверить заново — `tools/geo/verify-countries.js`
и `tools/geo/verify-cities.js`.

Места наполнены из OpenStreetMap ([ADR-0006](docs/adr/0006-map-provider.md)):
у всех пятидесяти есть координаты, местное написание и ссылка на запись
в источнике. `visit_minutes` пуст у всех — карта его не даёт, а выдумывать
время посещения запрещено критериями приёмки.

`duration_minutes` заполнен у всех 12 активностей и до 16.09.2026 не читался ни одним
запросом — это то самое время посещения, из которого планировщик строит день.

Открыто:

1. **Запись в базу закрыта для всех — админка не работает.** Политики применены,
   и запись разрешена только аутентифицированному автору своих записей. Входа
   (Supabase Auth) нет, поэтому `admin.html` не может ни добавить место, ни удалить его:
   запрос отклоняет RLS. Чтение при этом работает: города видны всем, места
   и маршруты — только опубликованные.

   Обходной путь есть и он рабочий: данные заводятся через интерфейс Supabase или
   через MCP-коннектор Supabase из сессии агента. Наполнение базы не заблокировано —
   заблокирован только один способ наполнения.
2. **Нет аутентификации — и это осознанное решение, а не упущение.** ADR-0002
   отверг альтернативу «планировщик плюс аккаунты сразу»: недели работы до первой
   проверки гипотезы. Бриф говорит то же — «без аккаунтов».

   Поэтому вход **не является** блокирующей задачей: он нужен для авторства мест,
   «Моих поездок» и работы админки, но ни то, ни другое, ни третье не проверяет
   основную гипотезу продукта. Браться за него — значит менять ADR-0002,
   а это решение владельца и новый ADR.

   (Формулировка «блокирующая задача номер один» стояла здесь с 16.09.2026 и была
   неверной: она противоречила ADR-0002. Исправлено в тот же день.)
3. **Планировщик построен на допущениях, а не на согласованных числах.** Расчёт
   работает (`assets/js/planner.js`, `plan.html`), но окно дня, длительность
   посещения по умолчанию, скорость, поправка на извилистость и порог «рядом» —
   мои допущения. Они видны пользователю на странице плана и отменяются одним
   словом владельца. Вопросы Q5–Q10 в `docs/ACCEPTANCE-PLANNER.md`.
   Отдельно: время в пути считается **по прямой** — настоящих маршрутов
   транспорта у нас нет.
4. **Старые активности не связаны с местами.** Поле `place_id` есть, но заполнено
   у нуля из 12 активностей: все они хранят текст и в планировании не участвуют.
   (До 16.09.2026 здесь стояло «из 36» — число от состояния до удаления задвоенного
   маршрута. Сверено запросом к базе.)
5. **Админка не редактирует**, только добавляет и удаляет. Города через UI не заводятся.
6. **Маршрут «за 5 дней» пуст.** Обещает пять дней, а дней и активностей у него ноль.
   16.09.2026 снят с публикации, чтобы посетитель не открывал пустоту. Не удалён:
   похоже на незаконченный черновик. Либо наполнить, либо удалить — решение открыто.
7. **Время посещения не заполнено ни у одного места.** `visit_minutes` пуст
   у всех 50: OSM его не даёт, а выдумывать запрещено. Планировщик без этого
   числа день не построит — он будет подставлять своё и помечать подстановку
   (допущение A3 в критериях приёмки). Закрывается либо ответом владельца
   на вопрос Q6, либо вторым источником.
   Города, кроме Гуанчжоу, по-прежнему пусты.
8. **Нет SRI у стороннего скрипта.** Версия `supabase-js` зафиксирована, но `integrity`
   не выставлен: посчитать хэш можно только по файлу, который реально отдаёт CDN,
   а из рабочей среды агента jsDelivr недоступен. Неверный хэш положил бы все страницы.
   Делается владельцем с обычной машины — см. `.claude/rules/security.md`, правило 4.
9. **План набивает первый день и оставляет остальные пустыми.** Проверено
    в браузере 16.09.2026: четыре места на два дня легли все в первый день,
    второй остался пуст и получил предупреждение «простой 12 ч». Формально
    расчёт честен — он показывает и простой, и пустой день. Но ADR-0002 обещает
    план «без провалов по времени», а пустой день — это и есть самый большой
    провал. Чинится раскладкой по дням с выравниванием, но «набивать подряд»
    против «растягивать поровну» — продуктовый выбор, а не технический.
    **Требует решения владельца.**
10. **Сайт выглядит как два разных сайта, и это решение владельца.** Первая
    страница тёмная, по оформлению прототипа; `city.html`, `plan.html`
    и `admin.html` остались светлыми. Владелец назвал нынешнее оформление
    проекта плохим и отложил замену: «перенесем дизайн глобуса в следующий
    раз, сейчас только первую страницу делаем». Человек, перешедший с глобуса
    в город, попадёт в другой вид — это известная цена. Допущение A4
    в `docs/ACCEPTANCE-GLOBE.md`.
11. **Собранный движок может разойтись со своим исходником.**
    `assets/vendor/globe-engine.js` — машинный файл: на ревью он выглядит как
    «поменялся мегабайт минифицированного кода». Если кто-то поправит
    `tools/globe/` и забудет пересобрать, в репозитории будет лежать старая
    сборка, и заметить это глазами нельзя. Закрывается проверкой в CI, которая
    пересобирает и сравнивает; **не сделано**. Риск назван в ADR-0008.
12. **Справочник приходит по сети при каждом открытии первой страницы.**
    235 стран с очертаниями и 9045 городов, без кэша. Без сети страница
    покажет планету, но ничего не найдёт. Смягчения нет: преждевременно,
    пока страницу никто не открывает. Сколько это весит на самом деле —
    техдолг №18.
13. **Девять переводов сделаны без носителей языка.** Русский и английский
    выверены, остальные восемь — перевод на глаз. Админка вообще только
    на русском и английском, остальные получают английский запасным путём.
    Это цена входа, а не готовая локализация (ADR-0009).
14. **Часть текста остаётся русской на любом языке.** `NF.dates.formatHuman`
    даёт «1 апреля» из собственного словаря месяцев; `NF.planner` отдаёт
    готовые русские предупреждения и причины отбрасывания; `NF.trip.missing`
    отдаёт русские названия того, чего не хватает. На странице плана
    иностранец увидит смесь.
15. **Проверка политик RLS из браузера не сделана.** Сценарий записан в конце
    `supabase/policies.sql` и ждёт владельца: из рабочей среды агента сеть
    до `*.supabase.co` закрыта, проверялось только со стороны базы.
16. **У справочника две двери, и вторая ошибается.** `tools/geo/load-reference.js`
    отправляет файл в базу как есть. Агент в сессии так не умеет: сети до
    Supabase из его среды нет, и содержимое файла он пересказывает в параметр
    инструмента — то есть переписывает мегабайт цифр руками.

    Это уже соврало дважды. У Мексики в контуре появилось `[-97.17,15.91]`
    вместо `[-97.18,15.91]` — одна цифра из тридцати двух тысяч точек.
    А у семи маленьких стран (KM, LU, SG, SM, TT, WS, TF) `spread` остался
    от более ранней сборки: 5 вместо 0,4, то есть камера на клике по Сингапуру
    останавливалась бы над всей Юго-Восточной Азией. Оба раза находила сверка,
    а не глаза; второй раз — уже `verify-countries.js`, написанный после
    замечания ревью, что сверка городов смотрит не на ту таблицу.

    Поэтому: **после любой заливки руками — обе сверки**,
    `node tools/geo/verify-countries.js` и `node tools/geo/verify-cities.js`.
    Они считают суммы и хэши по всему справочнику и сравнивают с источником;
    у городов ключ `--chunks` показывает, какая порция разошлась.

    Состояние на 17.09.2026: сверены и страны, и города, **сошлись полностью** —
    234 строки стран и 32 323 точки очертаний, 9045 городов и хэш их названий.
17. **Ватикан лежит в точке 0°, 0°.** У Natural Earth 1:50 млн нет геометрии
    для Ватикана — он меньше разрешения карты, — и генератор его пропускает.
    В базе строка `VA` всё-таки есть: без контура, с координатами 0/0, то есть
    в Атлантике у берегов Африки. На глобусе он не выбирается (выбор идёт
    по контуру), но в поиске находится и уводит камеру в океан.
    Чинится либо настоящими координатами (41.9029, 12.4534) без контура,
    либо удалением строки. **Требует решения владельца:** это данные о том,
    что считать страной в справочнике, а не техническая мелочь.

18. **Первая страница тянет 671 КБ справочника вместо обещанных 400.**
    Замерено 17.09.2026 на настоящих данных: страны 181 КБ gzip, города
    без написаний 230 КБ, написания ещё 260 КБ. Критерий AC-008 обещает
    не больше 400 КБ на весь справочник — превышение в 1,7 раза. Бандл
    и текстуры при этом в норме.

    Неожиданным оказался источник веса: не очертания стран, а города.
    Страница просит все 9045 сразу и вместе с написаниями на десяти языках,
    хотя подписи показывает только у выбранной страны.

    Половина чинится без потери поведения — не тянуть `names` для всех
    городов, а брать их по выбранной стране: останется 411 КБ. Вторая
    половина — развилка, и она **требует решения владельца**: мгновенный
    поиск по всему справочнику прямо в браузере против лёгкой первой
    загрузки с поиском на стороне базы. Это выбор между двумя разными
    продуктами, а не оптимизация.

## С чего начинать

Порядок работы описан в [.claude/rules/development-workflow.md](.claude/rules/development-workflow.md).
Коротко: «зачем» зафиксировано в `docs/PRODUCT-BRIEF.md`; дальше — критерии приёмки
(`intent-driven-development`), план, код.

**Суть продукта одной строкой:** боль не в том, что человек не знает, *что*
посмотреть, а в том, что он не знает, *в каком порядке* — и теряет дни на возвраты,
крюки и простои. Всё остальное вторично.

Шаг «зачем» закрыт брифом, шаг «критерии приёмки» — файлом
[docs/ACCEPTANCE-PLANNER.md](docs/ACCEPTANCE-PLANNER.md), ревизия 2.

Первый сквозной срез планировщика **написан** (ADR-0007). Из десяти вопросов
к владельцу отвечены два; остальные восемь не блокируют код — каждый подменён
действующим допущением, и эти допущения показаны пользователю прямо на странице
плана. Ответ владельца теперь не открывает дорогу коду, а **меняет числа
в уже работающем плане**.

## Правила

Все правила проекта — в [.claude/rules/](.claude/rules/README.md). Ключевое:

- Пользовательские данные **никогда** не идут в `innerHTML` — только `textContent`
  (с 16.09.2026 за этим следит хук `warn-on-innerhtml.sh`, но хук предупреждает,
  а не запрещает: думать всё равно надо)
- Единственная реальная граница безопасности — RLS на стороне Supabase,
  а не то, что скрыто в интерфейсе
- Продуктовые ограничения не выводятся из кода — только от владельца проекта
- Архитектурные развилки фиксируются в `docs/adr/`
- Перед коммитом — `npm test`. С 16.09.2026 это не пожелание, а шлюз:
  хук `run-tests-before-commit.sh` блокирует коммит на красных тестах,
  а `.github/workflows/test.yml` повторяет проверку на стороне GitHub
- Голое слово «маршрут» не употребляем: либо «авторский маршрут», либо «план».
  Термины и границы — в [docs/GLOSSARY.md](docs/GLOSSARY.md)
- Утверждение о состоянии базы проверяется **запросом к базе**, а не чтением файла
  рядом. Рядом с фактом полезно писать дату, когда его в последний раз сверяли

## Опыт другого проекта владельца

У владельца есть зрелый проект [wb-analytics](https://github.com/Masreniy/wb-analytics)
с 272 PR и выстраданными правилами. Что оттуда взято и что сознательно не взято —
в [docs/TRANSFER-FROM-WB.md](docs/TRANSFER-FROM-WB.md).

Правила поведения оттуда уже перенесены в `.claude/rules/development-workflow.md`.

Четыре самых важных для планировщика пункта: даты в трёх часовых поясах —
**сделано** (`dates.js`); чистая функция расчёта — **сделано** (`planner.js`);
объяснение любого вычисленного числа — **сделано** (блок «На чём построен этот
расчёт» на странице плана). Не сделан четвёртый: фильтра мест на странице города
пока нет вовсе, поэтому и резать набор на входе расчёта нечем.
